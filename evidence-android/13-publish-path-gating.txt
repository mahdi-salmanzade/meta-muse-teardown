# Android background publishing: human-in-the-loop (HITL) gate coverage
# Static review of extracted-apk/jadx/sources (com.facebook.aura 8.0.0.21.168).
# Nothing was installed or run. Line numbers refer to the jadx output.
# Many methods quoted here are Kotlin coroutines that jadx marks "Code decompiled
# incorrectly". Where that affects a conclusion, it is noted inline.

SUMMARY
The gate is not applied at the network sink. It is applied by each caller, and only
when NodeHitlCatalog.forDataSource(sourceId) returns a spec. forDataSource returns a
spec for exactly six sources: health, contacts, calendar, call_log, sms, notifications.
Every path for location (geofence crossings), network_state (Wi-Fi SSID/BSSID/RSSI,
carrier, roaming) and battery publishes to client.data_source.publish with no HITL check.
The LOCATION NodeHitlGroup exists but nothing maps to it.
Gated READ categories publish silently with no prompt when the per-category mode is
"allow" OR is unset while the cached server "connector_default" is auto_allow. A
missing or unrecognised server value is parsed as AUTO_ALLOW.

Resulting truth table (READ categories; every proactive spec is READ):
  per-category pref "<group>_read" | cached connector_default         | PROACTIVE_SYNC result
  "allow" (always allow)           | any                              | Allowed, silent
  "deny"                           | any                              | Denied
  "ask"                            | any                              | Denied (never prompts)
  unset                            | nothing cached                   | ALWAYS_ASK -> ASK -> Denied
  unset                            | auto_allow                       | ALLOW -> Allowed, silent
  unset                            | always_ask                       | ASK -> Denied
  unset                            | server omitted / unknown string  | parsed AUTO_ALLOW -> Allowed, silent
DATA_SOURCE_BACKFILL uses the same modes. ASK prompts only when canPrompt, the app is in
the foreground, or a background session is active. Otherwise it is Denied.

7. What the code proves vs what is uncertain
======================================================================
PROVEN (static):
- No gate in the publish sink or pipeline. Gating is per caller and keyed on forDataSource().
- forDataSource() returns null for location, network_state, battery, geofences, alarms, reminders.
- Geofence-crossing coordinates, network_state (SSID/BSSID with fine location) and battery
  publish without any HITL check. HatchBootReceiver re-arms geofences and triggers
  network_state after reboot.
- PROACTIVE_SYNC never prompts. It is silent-allow or deny.
- A missing or unknown connector_default in the server response is stored as AUTO_ALLOW.
UNCERTAIN:
- The actual server value of connector_default for a new account. It is not in the APK.
- Exact post-check branching in ProactiveSyncRunner, AuraProactiveSyncWorker and
  NotificationsDataSource (jadx "decompiled incorrectly"; smali not reviewed).
- Whether the N1 AllowAll race can occur in practice.
- Runtime OS limits (permissions, Doze, background-location grant) that can still block
  individual paths.
