16 - NETWORK & PROTOCOL MAP (Android 8.0.0.21.168, com.facebook.aura)  [S5, static only]
==========================================================================================

Method: static reading of the jadx decompilation (extracted-apk/jadx/sources), the decoded binary
manifest (extracted-apk/manifest-tree.txt), the network-security-config resource decoded from
extracted-apk/raw/res/t0.xml (resource 0x7f150002, resolved via resources.arsc), `strings` over
extracted-apk/raw/lib/arm64-v8a/*.so, extracted-apk/raw/assets/ and the *.properties SDK version files.
Nothing was installed, executed or network-contacted.

Path shorthand: "aura/" = extracted-apk/jadx/sources/com/facebook/aura/ ; "X/" = obfuscated
extracted-apk/jadx/sources/X/ ; "lib:" = a string inside extracted-apk/raw/lib/arm64-v8a/<name>.so.

CAVEAT: a hostname, URL, method name or field name in code shows capability, not behaviour. It does not
prove a connection is made, when it is made, or what is actually sent. Server-side MobileConfig flags
(MC.*) can switch many paths on or off. Secrets/keys are shown as [REDACTED].

## 2. PROTOCOL / RPC MAP
------------------------
Transport: one WebSocket per user to the VM gateway (wss, server-supplied vm_ws_url), carried inside a
Noise channel (section 3). JSON frames {"type":"req"|"res"|"event", "id", "method"|"event", "params"|"payload",
"seq"} (aura/gateway/JarvisProtocol.java, JarvisProtocolJsonKt.java, HatchGatewayNetworkLogRecorder.java: "req",
"res", "evt"/"event", "method", "ok"). Inbound frames are dispatched in
aura/gateway/HatchGatewayEventsHandler.java (by "event", else by "method"); the ONLY inbound request method
that is routed is client.invoke ("inbound req method=... has no route" otherwise).

### 2c. Heartbeat / ack / backfill ack
  - Keepalive: connection.ping (D->M request) and gateway keepalive ping
    (aura/gateway/HatchGatewayConnection$GatewayConnectionEngineHost$sendKeepalivePing$1.java). No node.heartbeat.
  - Invoke delivery: client.invoke carries invoke_id; device replies client.invoke.result; duplicates are dropped
    ("client.invoke: dropping frame - invokeId=...", "redelivered_dropped", aura/nodes/datasource/InvokeResultAck.java).
  - Backfill: gateway sends client.invoke command "data_source.backfill" with start_date/end_date; device replies
    (client.invoke.result) with BackfillAckJson {status:"backfill_initiated", delivery_mode:"chunked_v1",
    transport:"client.data_source.publish", source, start_date, end_date, estimated chunks, chunk_policy}
    (aura/nodes/datasource/BackfillAckJson.java). ChunkPolicyJson from DataSourcePublishPipeline.java:
    chunk_days (per source), max_chunk_bytes 1048576 (1 MiB), max_chunks 256, max_total_bytes 67108864 (64 MiB),
    may_bisect true; frame cap "4194304B wire limit". These advertised policy values differ from
    enforcement: 256 chunks / 64 MiB total trigger warnings and CONTINUE; 1 MiB is a page-sizing target
    that can be exceeded by a single item. The separate wire-size check rejects frames over 4 MiB.
    See DataSourcePublishPipeline.java:80-108,160-175,532-555 and evidence/17-commit-audit.txt.
    Chunks then stream as client.data_source.publish with
    operation "reconciliation_page". Proactive (non-backfill) publishes use operation "proactive".
  - node.register / node.heartbeat / node.invoke.result / node.list / node.unpair and /nodes/* path strings exist
    only in lib:libstartup.so (shared xplat gateway method->path table, same as macOS). The Android Java node client
    uses the client.* methods above instead; node.invoke.request is absent.
