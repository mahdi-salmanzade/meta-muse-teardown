1. Training scope and defaults
Public: [R] describes training on conversations, tool calls and subagent handoffs,
with sanitization of key personal information and an opt-out. [L] also mentions opt-out.
App: macOS W@46274201 trainingEnabled??!0 is a UI fallback, not a captured account
setting. Android HatchAiTrainingApi.java:24 DEFAULT_ENABLED=true and
ProductImprovementsResponseJson.java:78,85 also default true. iOS text does not establish
the default. All three have a switch and copy describing future opt-out effects.
Android Health Connect R-ID 0x7f1206e7 says its information forms part of interactions
which Meta MAY use to improve AI. The generic connector footer uses “use”, not “may”.
iOS B@60850272 and macOS W@42158098 have related task/connector-data disclosures.
Assessment: connector footers are more specific about types such as health. They do
not establish that all raw records train models, nor that connector-derived data was
excluded from the public term “tool calls”. Opt-out enforcement and treatment of
already-collected data remain untested. Client fallbacks do not establish live defaults.

2. Access, automatic sharing and history
Public: [L] describes choosing connections/access and being able to disconnect.
App: macOS W@42164539 describes automatic message sharing; W@42164742 distinguishes
Mail sender/subject auto-sync from message text on request. The dialog fallback at
W@42172078 is on; W@42172253 saves it when connecting. Android Calendar/Contacts
R-IDs 0x7f1206d0/0x7f1206d2 describe storing existing information. iOS camera-roll
copy at B@61127088 presents a switch, without establishing its initial state.
Assessment: these are material details of consent, not proof that user choice is
absent or that automatic sharing contradicts the public statement. History depth,
production defaults and behavior following denial still need measurement.

3. Approvals
Public: [L] promises checks for sensitive actions; [R] expressly allows read-only,
previously allowed and low-risk actions without interruption.
App: macOS W@46301967 labels auto_allow as “Ask for some actions”; W@46302002 says
“Before every write and some read actions”. Android defaults READ to ALLOW and WRITE
to ASK, subject to saved modes and the connector baseline. “Always allow” is available.
Assessment: unprompted reads are consistent with the public distinction. A UI label
is not proof that every write always prompts or that every command is locally gated.
Android's no-cache / missing-field distinction is in evidence-android/13 and evidence/17.

4. Disconnecting, message deletion and memory
App: macOS W@20718706, Android R-ID 0x7f1206c4 and iOS B@60853104 distinguish stopping
new access from deleting prior data. iOS forwarding copy at B@60863824/B@61192396 also
says previously shared messages are not deleted by disconnecting.
Android R-ID 0x7f120592 and iOS B@61405342 say a deleted message MAY stay in agent memory.
Assessment: disconnect is not an erasure operation. Message deletion may leave derived
memory; the earlier categorical “does not delete memory” conclusion was too strong.
Public: [L] describes asking Muse to forget; [R] describes inspecting/editing/downloading
VM files, including memory. Neither is a demonstrated backend-erasure guarantee.

5. Reset and backups
Public: [R] describes continuous VM backups.
App: reset copy lists chat history, files, artifacts and tasks after “including”
(macOS W@46237186/W@46240659, Android R-IDs 0x7f120acd/0x7f1205bc, iOS B@61120832).
Assessment: that list is non-exhaustive; omission of memory does not establish exclusion.
Backups and permanent deletion can coexist. The reviewed statements do not establish
backup-deletion timing or treatment of training copies. A client test can inspect
visible results, not certify backend erasure. No account-deletion flow was verified.

6. Support and human access
Public: [R] allows operational access under policy for the current service; [L] describes
Confidential VM as a future offering.
App: support copy at Android R-ID 0x7f120536 / iOS B@61110928 says granting access exposes
chats, memory and files and ends confidentiality; related copy makes access revocable.
Bug-report copy (macOS W@16861405, Android R-ID 0x7f12012e, iOS B@62514208) includes recent
conversation details/device logs unless deselected. iOS B@62514608 describes review.
Assessment: the warning belongs to a support-access flow, not evidence that all current
VMs prevent operator access. A shared “Media human review” setting with no linked handler
does not establish a Muse conversation-review process.

7. Advertising and email filtering
Public: [L] says conversations/VM data are not shared with Meta's ad systems. [R] describes
filtering email tokens and login/reset links.
App: Android has an Advertising ID attribution path (evidence-android/16); this is not
proof that conversation/VM content goes into ads. Local Mail header sync and the Android
SMS/notification paths do not establish where the described email filter runs.
Assessment: measure attribution conditions and email/SMS/notification filtering separately.

Open: runtime defaults, enforcement, selected payloads, training use, deletion and backup
retention. No claim of verified server behavior follows from these UI strings.
