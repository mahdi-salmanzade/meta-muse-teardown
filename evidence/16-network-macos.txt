## 2. PROTOCOL / RPC MAP

### 2a. Transport shape
  The app keeps one long-lived gateway connection to the user's agent VM ("Jarvis connection" in logs):
  WSS to hatch.metaaivm.com/v1/noise?vm_id=... (or a per-VM *.metaaivm.com host), wrapped in a
  Noise_XX_25519_AESGCM_SHA256 channel (sec. 3d). Frames are JSON-RPC-like: `type` req/res/event, `id`,
  `method`, `params`, `payload`; "unsupported gateway method: " and "RPCs already pending" errors exist.
  Each native method string is paired with an HTTP-style route (the gateway multiplexes HTTP-shaped
  requests over the Noise stream: HCHNoiseGatewayCarrierBridge, "TigonNoiseService", noise_stream ids).

## 3. TRANSPORT SECURITY

### 3a. Network stacks
  Tigon + MNS (Meta network stack): HTTP2_TCP, HTTP3_QUIC (mvfst), Fizz TLS 1.3 (fizz_handshake_success,
  fizz_ech_* = Encrypted Client Hello fields), "MNS SecureTCP WebSocket transport", mbedTLS strings, proxygen.
  "TigonMNSWithFallbackService", "Meta AI VM domain uses OS fallback" -> VM-domain traffic can fall back to
  the OS stack. ATS: Info.plist has NO NSAppTransportSecurity key (default ATS applies to URLSession/WebKit;
  Tigon/MNS sockets are outside ATS).

### 3b. Certificate pinning / trust
  "_CalculateCertPin", "Pinning validation failed.", "Certificate is revoked.", CRL parsing
  ("Invalid CRL.", "Leaf signature verification failed."), "MNSCertificateVerifierApple".
  "FBWhitehatSSLPinningBypass" - Meta's whitehat setting that lets bug-bounty researchers disable pinning.
  No base64 SPKI pin hashes appear as strings (pins, if any, are not stored as text).
  Embedded DER certificate: "CN=Facebook Rootcanal Prod Root CA, O=Facebook Inc." (self-signed, valid
  2018-02-21 to 2048-02-21, sha256 76:03:12:4D:49:0B:2C:64:70:64:23:59:CF:6B:48:DA:34:25:80:88:36:53:09:9E:E5:48:81:2E:72:46:02:C7)
  plus a 2048-bit RSA public key, next to MNSCertificateVerifierApple. Whether it is an extra trust anchor
  or a pin target is not determinable.
  Imported Security calls (nm -u): SecTrustSetAnchorCertificates, SecTrustSetAnchorCertificatesOnly,
  SecTrustCreateWithCertificates, SecTrustEvaluateWithError - i.e. the app can evaluate chains against its own
  anchor set instead of the system store. Unlike iOS (CACerts.plist, 143 roots) no bundled CA list file
  exists in Contents/Resources; which anchors are used is not visible.
  Meta domain classifier list includes pinningtest.appspot.com / insecure.pinningtest.appspot.com /
  fbpinningtest.appspot.com test hosts and Meta .onion addresses.

### 3c. Cleartext
  Tripwires: "Attempt to send a plaintext HTTP request to a Meta or Ohai domain", "... to a Meta AI VM
  domain", "Tagged Meta plaintext request", "Tripwire failed". TigonRequestSanitizationInterceptor
  categories: plaintext / ohttp / meta_ai_vm / third_party with header_stripped,
  query_parameter_would_be_stripped, needsMetaAIVMAuth.
  Allowances: extension manual pairing accepts ws:// (normalizeWsUrlForCredentialSource; already in
  evidence/12); web parseGatewayUrl accepts ws: or wss:; local CDP is http://127.0.0.1.

### 3d. End-to-end channel to the VM (Noise + attestation)
  "Noise_XX_25519_AESGCM_SHA256" (N and W), NoiseHandshake writeMessage1/readMessage2/writeMessage3,
  "Noise carrier has no active channel; failing closed (no plaintext send)."
  Private auth / notary: notary_token, "private-auth notary token must be nonempty", vm_notary_tokens,
  fetchedWithNotarySupport, noise.handshake.private_auth.vm_proof_failed / enrollment_required /
  key_required, noise.handshake.attestation_failed, "Refusing a confidential VM that did not prove itself
  (privateAuthVerified=false)", request(carrierURL:...:expectedChipIds:...),
  -[HCHNoiseGatewayCarrierBridge initWithSevSnpVerifierEnabled:transparencyPolicy:...].
  W contains an AMD SEV-SNP attestation report parser (chipId, reportedTcb, measurement) with VCEK
  certificate cross-checks, and createStrictSharedAgentNoiseTrustEvaluator. N also contains
  facebook::tigon::noise::NoiseAlwaysAcceptAttestationVerifier (an accept-all verifier class, as on iOS).
  BUT: W reads MobileConfig hatch_web:attestation_enforce_mode with default 0 = "Off" (1 = Staging, 2 = Prod),
  overridable by a server-provided tier. Native enablement is a runtime argument. Whether attestation is
  enforced for a given user is server-configured and not statically determinable.
  Verified-identity headers: x-hatch-verified-uid, -media-path, -media-version, -media-variant,
  -notary-spaces, x-hatch-noise-active, x-noise-connection-id.

### 3e. OHTTP
  Native: relay/config hostnames only as domain-list entries, plus headers x-fb-ohttp-no-user-country-forwarding
  and x-ohttp-new-vip; no "message/ohttp-req" media-type string in the native binary.
  Web: OhaiRelayClient / FixedOhaiClient (message/ohttp-req, message/ohttp-res, KEM X25519-HKDF-SHA256;
  PROHIBITED_INNER_HEADER_PREFIXES proxy-, sec-, x-b3-, x-datadog-, x-forwarded-). The only feature found
  using it: CVM lease - "Reserve anonymously through ACS over OHTTP, then bind the CVM to your signed-in
  account.", gated by hatch_web:hatch_acs_ohai_enabled (default false in code). This identifies a
  reservation path; no wrapper for chat/sync/telemetry was identified in the inspected code.
  It does not establish every runtime route or global relay scope.

### 3f. Tokens in URLs
  Native strings "auth_token=", "notary_token=", "vm_id=" beside the Noise WSS connect log line.
  Extension buildAuthenticatedWsUrl() sets ?auth_token=<token>. Web shared-agent ingress builds
  wss://hatch.metaaivm.com/v1/noise?vm_id=&auth_token=&app_id=&request_id=. Query-string credentials can be
  recorded by intermediaries' access logs; TLS still protects them in transit.

### 3g. Update channel
  Sparkle 2.7.0-beta.1 over HTTPS with EdDSA-signed updates (SUPublicEDKey). No SUEnableSystemProfiling key,
  so Sparkle's optional system-profile upload is not enabled in Info.plist.
