16 - NETWORK & PROTOCOL MAP (iOS 8.1.0, com.facebook.hatch)  [S5, static only]
==================================================================================

Method: strings(1) of all five Mach-O binaries (HatchApp, Frameworks/MobileConfig.framework/MobileConfig,
PlugIns/HatchNotificationServiceExtension.appex, HatchShareExtension.appex, WidgetExtension.appex);
otool -L and nm -u on HatchApp; plutil on Info.plist files; CACerts.plist decoded with plistlib + openssl x509;
MobileConfig parameter names read from params_maps/params_map.txt; bundled JS (novnc/, pptxviewer/) grepped.
No disassembly, no execution, no network contact with any host listed here.

Caveats:
- The IPA is a FairPlay-decrypted dump whose code signature fails strict verification
  (see evidence-ios/01-authenticity.txt). Treat every string as "present in this sample", not as
  proven Meta-shipped code.
- A hostname, path or method name shows that code refers to it. It does not show that the app
  connects to it, when, or with what payload. Many strings come from shared Meta libraries.
- The flat host list is in evidence-ios/09-endpoints.txt. This file reorganises it by role and adds
  protocol, transport, telemetry and SDK findings. "NEW" marks items not in 09.

## 3. Transport security
------------------------------------------------------------------------------------------

### 3a. App Transport Security
  No NSAppTransportSecurity key in the main Info.plist or in any of the 3 extension Info.plists (all checked).
  => default ATS for URLSession and WKWebView (HTTPS/TLS 1.2+). ATS does not govern Meta's own Tigon/MNS/Fizz
     socket stack, which does most Meta traffic.
  UIBackgroundModes: audio, fetch, location, remote-notification. BGTaskScheduler ids:
  com.meta.hatch.cameraroll.sync.processingTask, com.meta.hatch.nodedata.sync.refreshTask.

### 3b. Bundled trust store: CACerts.plist - NEW
  Array of 143 DER certificates, all public WebPKI roots (COMODO/USERTrust, DigiCert G3/G4/G5, GlobalSign R3/R6/R46/E46,
  ISRG X1/X2, GTS R1-R4, Amazon 1-4, Microsoft 2017, Sectigo R46/E46, Entrust, QuoVadis, SSL.com, HARICA, D-Trust,
  TrustAsia, BJCA, emSign, NAVER, etc.). No Meta-private CA and no leaf certificates.
  Strings: "CACerts", "Caught Exception loading CACerts:"; Security imports SecTrustSetAnchorCertificates and
  SecTrustSetAnchorCertificatesOnly.
  => Meta's network stack validates against its own bundled root list rather than only the iOS store. A user- or
     MDM-installed root is therefore unlikely to be trusted by that stack (inference; matches pinning telemetry below).

### 3c. Certificate pinning
  proxygen::httpclient::PinningData, PinningSSLCallbacks, "_CalculateCertPin", "Pinning validation failed.",
  "Certificate is revoked.", "No certificates in the chain.".
  Pin telemetry fields: verified_pinning_{reason,required_hash,user_hash,excluded_hash,required_found,
  user_installed_found,user_installed_count,excluded_found,time_pin,host,success}.
  Bypass switch string: "FBWhitehatSSLPinningBypass" (Meta's bug-bounty "whitehat" setting; its availability in
  this build is not determinable). Test hosts in classifier list: insecure.pinningtest.appspot.com, pinningtest.
  No SPKI hash values were found as plain base64 strings (pins, if present, are not stored that way).

### 3d. TLS stack and plaintext guards
  Fizz TLS 1.3 ("TLS 1.3, client CertificateVerify", fizz::client::ECHPolicy, proxygen::httpclient::ProxygenECHPolicy,
  fizz_ech_sni, fizz_ech_config_id, ech_configs) = Encrypted Client Hello support; HTTP/3 (proxygen HQSession);
  mbedtls in the MNS WebSocket stack.
  Plaintext tripwires: "Attempt to send a plaintext HTTP request to a Meta or Ohai domain",
  "Attempt to send a plaintext HTTP request to a Meta AI VM domain", "Not a Meta or Ohai domain".
  TigonRequestSanitizationInterceptor categories: plaintext, meta_ai_vm, clips_save_to_camera_roll_third_party,
  (ohttp); fields query_parameter_would_be_stripped, header_stripped, redacted_url, sanitizedUserAgent, needsMetaAIVMAuth.
  Only cleartext URL templates: "http://%@" (generic), WebRTC/XML namespace URIs, CRL/OCSP URLs in certificates.
  Bundled noVNC connects to a placeholder "wss://bridge.invalid/" that the app bridges natively
  (HCHGatewayVNCDuplexStream), so the VNC view makes no direct network connection of its own.
  In-app auth WebView: "configureLabProxy(_:)" / "[AuthWebView] configured HTTP CONNECT proxy for web content",
  driven by LAB_PROXY_HOST / LAB_TRANSPARENT_PROXY_HOST (test-lab variables; not a production proxy).
  Payments: hatch_ios:skip_fbpay_cert_verification + "shouldSkipCertVerification" belong to the Meta Pay
  payment-token (PTT) encryption-key trust chain, not TLS.

### 3e. OHTTP ("OHAI")
  Library: facebook::tigon::ohai::{TigonOhaiService, OhaiConfigManager, SignedOhaiConfigVerifier, TigonOhaiBodyProvider,
  OhaiBridgingToken}, fizz::hpke, proxygen::ohai::ChunkedOhaiClientRequestEncoder; content types message/ohttp-req,
  message/ohttp-chunked-req, message/bhttp; "decryptDeidentifiedTigonResponse".
  Allow-lists: "Unallowed OHAI proxy url: {}. Allowed proxy URLs: [{}, {}, {}, {}, {}]" (5 relay URLs, 1g) and
  "Unallowed OHAI GraphQL query: {}. Allowed GraphQL queries: [{}]" (query names are filled at runtime).
  Fail-closed: "OHAI-intended request received while OHAI is disabled; failing closed to avoid sending an
  un-deidentified request." Header "x-fb-ohttp-no-user-country-forwarding".
  MobileConfig: fbios_ohai:ohai_relay_proxy_url, mios_ohttp_target_new_vip.
  Traffic the strings tie to OHTTP: (1) ACS token issuance and CVM lease/bind (2d); (2) an allow-listed set of
  GraphQL queries (DeidentifiedRequestOHAIConfig / DeidentifiedRequestACSToken); (3) possibly analytics:
  OneFabric options attach_acs_claim_to_batches, deidentified_events, onefabric_enable_acs_claim_minting.
  Nothing ties the VM gateway WSS, the Stefi HTTP API, chat, sync uploads or crash uploads to OHTTP; those strings
  sit with Bearer / "ABRA access token" credentials that identify the account.

### 4d. Crash / exit / bug reports
  Crash: Breakpad + Crashpad (FBBreakpadExceptionHandler, CrashpadWrapper, MinidumpMemoryListWriter,
  MinidumpThreadWriter, ProcessSnapshotMinidump::InitializeExtraMemory), upload to
  www.facebook.com/mobile/ios_breakpad_crash_logs/ from the app and the Notification Service Extension.
  Report parameters: BreakpadProduct, BreakpadVersion, BreakpadProcStartTime, BreakpadProcessUpTime,
  BreakpadExtraFile, qpl_events, gwpasan_stack.
  Termination/diagnostic schema: ...isJailBroken:appliedSamplingRate:userId:attributionId:..., memory and disk
  counters, lastShareExtensionCall, lastNotificationServiceExtensionCall, isCleanInstall; app-exit reports to
  www.facebook.com/mobile/reliability_event_log_upload/ (signal_based_stacktrace_gz_base64, crashed_session_id).
  MobileConfig mwa_ios_termination_reporter_config: enable_crashpad, enable_extra_report_data,
  extra_diagnostic_data_enabled, extra_diagnostic_data_env_variables_enabled, detailed_memory_usage_enabled,
  gwp_asan_*, metrickit_diagnostics_correlation_enabled.
  Can crash reports include user content? The strings show minidumps with thread and memory lists, extra files,
  userId and optional environment variables. Crashpad sanitisation classes exist (ProcessSnapshotSanitized,
  MemorySanitizer). Whether memory is sanitised in this app is not determinable.
  User-initiated bug report (api.meta.ai/hatch/bug_report and Flytrap /bug_attachments): screenshots with an
  annotation tool (text_detected / text_redacted / unredact), view hierarchy, "Connection State",
  voice_config.json, hatchery_vm_link, treatPayloadAsConfidential flag; hatch_ios:cvm_filtered_bug_report_enabled.

  Family Device ID and identifierForVendor logging: already covered in evidence-ios/10-notable.txt A.

## 6. What static analysis cannot determine
------------------------------------------------------------------------------------------
  - Which hosts are actually contacted, how often, and whether any traffic goes to the third-party hosts in 1i.
  - Payload contents of node.invoke.result, client.data_source.publish, chat.* and media_sync (see Phase 2 D3).
  - Whether Noise and SEV-SNP attestation are ON for a given account: enable_noise, noise_enabled,
    enable_snp_attestation_verifier and cvm_attestation_probe_enabled are server-side MobileConfig values, and an
    always-accept verifier exists. Even when on, the VM is Meta-operated: attestation limits who can read traffic
    in transit (the gateway), not what the agent software on the VM does with the data.
  - Which GraphQL queries go through OHTTP (the allow-list is filled at runtime), and whether analytics batches
    actually use ACS claims.
  - The pin set, and whether the whitehat pinning bypass is reachable in this build.
  - Whether crash minidumps are memory-sanitised, and default sampling and upload rates for any logger.
  - Server-side retention or linkage of any of this data.
